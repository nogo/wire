# Translate Anthropic API format

## Outcome
When a backend has `provider: anthropic`, wire translates incoming OpenAI-format requests to Anthropic Messages API format before proxying, and translates responses back to OpenAI format. Apps always speak OpenAI to wire regardless of the backend provider.

## Values
1. Correctness — translation preserves all semantics: messages, tool calls, tool results, streaming events, usage.
2. Streaming fidelity — Anthropic SSE events are translated to OpenAI SSE events in real-time, not buffered.
3. Reuse — extract proven translation logic from forge's provider code rather than reimplementing.

## Context
- `internal/gateway/gateway.go` — the HTTP reverse proxy. Currently proxies requests as-is to backends.
- `internal/config/config.go` — `Backend.Provider` field: `"openai"` (default) or `"anthropic"`.
- Forge's provider code at `/home/nogo/Development/projects/forge/delta/internal/provider/`:
  - `anthropic/anthropic.go` — Anthropic client with request building (`buildBody`) and SSE stream parsing. Key functions: `convertMessage`, `convertBlock` for message format translation.
  - `anthropic/sse.go` — Anthropic SSE event parser. Event types: `message_start`, `content_block_start`, `content_block_delta`, `content_block_stop`, `message_delta`, `message_stop`.
  - `openai/openai.go` — OpenAI client with `buildMessages` for message format. Shows the OpenAI wire format.
  - `openai/sse.go` — OpenAI SSE format: `data: {...}\n\n` with `[DONE]` sentinel.
  - `provider/types.go` — provider-neutral types (`Message`, `ContentBlock`, `Delta`) that bridge both formats.
- Key format differences:
  - OpenAI: system message as `role: "system"`, tool results as `role: "tool"` messages, tool calls in `tool_calls` array.
  - Anthropic: system as top-level `system` field, tool results as `tool_result` content blocks, tool calls as `tool_use` content blocks.
  - OpenAI SSE: `data: {json}\n\n` lines, `data: [DONE]` sentinel.
  - Anthropic SSE: typed events (`event: type\ndata: {json}\n\n`), `message_stop` event.
- This project uses Go 1.26. Use `errors.AsType[T]` where applicable.

## Requirements

### 1. Request translation (OpenAI → Anthropic)
Function `TranslateRequest(openaiReq []byte) ([]byte, error)`:
1. Parse the OpenAI chat completion request JSON.
2. Extract the `system` message (role="system") → set as top-level `system` field.
3. Convert messages:
   - `role: "user"` with text → `role: "user"` with `[{"type": "text", "text": "..."}]` content blocks.
   - `role: "assistant"` with `tool_calls` → `role: "assistant"` with `tool_use` content blocks.
   - `role: "tool"` messages → fold into next `role: "user"` message as `tool_result` content blocks.
4. Convert tools: unwrap the `{"type": "function", "function": {...}}` wrapper → flat `{"name": ..., "description": ..., "input_schema": ...}`.
5. Map fields: `max_tokens` (required for Anthropic, default 8192 if absent), `temperature`, `top_p`, `stream`.
6. Set `model` from the backend config (not from the incoming request).
7. Return the Anthropic request JSON.

### 2. Response translation — non-streaming (Anthropic → OpenAI)
Function `TranslateResponse(anthropicResp []byte) ([]byte, error)`:
1. Parse Anthropic response.
2. Convert content blocks back to OpenAI format:
   - `text` blocks → concatenate to `choices[0].message.content`.
   - `tool_use` blocks → `choices[0].message.tool_calls` array.
3. Map `stop_reason` → `finish_reason` (`end_turn` → `stop`, `tool_use` → `tool_calls`).
4. Map usage fields.

### 3. Response translation — streaming (Anthropic SSE → OpenAI SSE)
Function `TranslateStream(anthropicBody io.Reader, w http.ResponseWriter)`:
1. Parse Anthropic SSE events from the reader.
2. For each event, emit the equivalent OpenAI SSE chunk:
   - `message_start` → first chunk with role="assistant".
   - `content_block_delta` with `text_delta` → chunk with `delta.content`.
   - `content_block_start` with `tool_use` → chunk with `delta.tool_calls[{index, id, function.name}]`.
   - `content_block_delta` with `input_json_delta` → chunk with `delta.tool_calls[{index, function.arguments}]`.
   - `message_delta` → chunk with usage.
   - `message_stop` → `data: [DONE]`.
3. Flush after each emitted chunk.
4. Track content block indices to map to OpenAI tool_calls indices.

### 4. Auth header translation
Anthropic uses `x-api-key` header, not `Authorization: Bearer`. When proxying to an Anthropic backend:
- Remove any `Authorization` header from the outgoing request.
- Set `x-api-key: <api_key>` from the backend config.
- Set `anthropic-version: 2023-06-01`.
- Set `content-type: application/json`.

### 5. Gateway integration
In the gateway's proxy logic, before proxying to a backend with `provider: "anthropic"`:
1. Read the request body.
2. Call `TranslateRequest` to convert to Anthropic format.
3. Create a new request to the Anthropic backend URL (`/v1/messages` endpoint).
4. If streaming: use `TranslateStream` to convert the response in real-time.
5. If non-streaming: read the response, call `TranslateResponse`, write the result.

For Anthropic backends, do NOT use `httputil.ReverseProxy` — the translation requires reading and rewriting both request and response. Use `http.Client` directly.

### 6. Tests
- Round-trip: build an OpenAI request, translate to Anthropic, translate back. Verify key fields preserved.
- System message extraction.
- Tool calls translation both directions.
- SSE event translation with mock Anthropic stream → verify OpenAI SSE output.
- Edge case: empty messages, messages with only tool results.

## Constraints
- `go build ./...` must pass.
- `go test ./...` must pass.
- Do not modify files outside the Modifies/Creates list unless strictly required.
- For the Anthropic translation, the request body must be fully read (necessary for format conversion). This is acceptable — chat API request bodies are small (KBs). Response streaming must NOT buffer — translate events as they arrive.
- Reference forge's code for the translation logic but do not import forge as a dependency. Copy and adapt the relevant mapping logic.

## Failure Modes
- **Tool call ID mismatch**: OpenAI and Anthropic use different ID formats. Wire must preserve the original IDs through the round-trip, not generate new ones. Detection: test tool call round-trip with specific IDs.
- **Streaming translation drops events**: a malformed Anthropic SSE event causes the translator to skip it. Detection: test with real Anthropic SSE recordings. Mitigation: log warnings for unrecognized events, don't drop the connection.
- **Missing max_tokens**: Anthropic requires `max_tokens`, OpenAI doesn't. If the incoming request omits it, wire must set a default (8192). Detection: test with request that omits max_tokens.

# Manage llama-server child processes

## Outcome
Wire can start, stop, and health-check llama-server child processes for each managed backend defined in config. Processes auto-restart on crash. External backends are health-checked but not managed. Each managed backend gets an auto-assigned internal port that is not exposed to the user.

## Values
1. Reliability — a crashed llama-server restarts automatically without manual intervention.
2. Low resource overhead — the process manager is a thin supervisor, not a heavy framework.
3. Clean shutdown — SIGTERM/SIGINT stops all children gracefully before exiting.

## Context
- `internal/config/config.go` — `Config`, `Backend` types. `Backend.IsManaged()` distinguishes managed from external.
- `Backend.Model` is a HuggingFace ref passed to `llama-server -hf <ref>`.
- `Backend.Pooling` being set means this is an embedding/rerank backend: add `--embedding --pooling <value>` flags.
- `Backend.Context` maps to `-c`, `Backend.GPULayers` maps to `-ngl`, `Backend.Extra` is appended verbatim.
- llama-server exposes `GET /health` returning 200 when ready, 503 when loading.
- This project uses Go 1.26. Use `signal.NotifyContext()` with `context.Cause()` for shutdown. Use `new(expr)` where applicable. Use `errors.AsType[T]` for typed errors. Use `log/slog` for all logging.

## Creates
- `internal/process/manager.go` — process manager that starts/stops/restarts llama-server children.
- `internal/process/manager_test.go` — tests for process lifecycle.

## Modifies
- `cmd/wire/main.go` — start the process manager after loading config.

## Requirements

### 1. Manager type
```go
type Manager struct { ... }

func New(cfg *config.Config, log *slog.Logger) *Manager
func (m *Manager) Start(ctx context.Context) error   // Start all managed backends
func (m *Manager) Stop() error                         // Stop all children
func (m *Manager) Healthy(name string) bool            // Health check by backend name
func (m *Manager) Addr(name string) (string, bool)     // Returns "http://localhost:<port>" for a backend
func (m *Manager) Swap(ctx context.Context, name string, model string) error // Hot-swap model
```

### 2. Port allocation
Auto-assign ports for managed backends starting from 19100, incrementing by 1 per backend. These ports are internal — never exposed in config or to the user. Use `net.Listen` on `:0` to find a free port, then close the listener before passing the port to llama-server (avoids port conflicts).

### 3. Process lifecycle
For each managed backend:
1. Build the `llama-server` command args from the Backend config.
2. Start the process with `os/exec.CommandContext`.
3. Redirect stdout/stderr to `slog` at debug level, prefixed with the backend name.
4. Poll `GET /health` every second, up to 120 seconds. Log when healthy.
5. If the process exits unexpectedly, restart it after a 2-second backoff (max 5 retries within 60 seconds, then stop retrying and log an error).

### 4. llama-server flags
Build the command as:
```
llama-server -hf <model> --port <port> --no-webui -ngl <gpu_layers> -c <context> [--embedding --pooling <pooling>] [extra...]
```
- Omit `-ngl` if `GPULayers` is 0.
- Omit `-c` if `Context` is 0 (llama-server uses its default).
- Add `--embedding --pooling <pooling>` only if `Pooling` is non-empty.
- Append `Extra` flags verbatim.

### 5. Hot-swap
`Swap(ctx, name, model)`:
1. Stop the running process for `name` (send SIGTERM, wait up to 10 seconds, then SIGKILL).
2. Update the backend's model in memory.
3. Start the new process.
4. Wait for health check to pass.
5. Return error if health check fails after 120 seconds.

### 6. External backends
For backends where `IsExternal()` is true: no process management. `Addr(name)` returns `Backend.URL` directly. `Healthy(name)` does a `GET <url>/health` (best-effort, returns true if the endpoint doesn't support health checks — some external APIs don't).

### 7. Shutdown
On context cancellation (SIGTERM/SIGINT), send SIGTERM to all children, wait up to 10 seconds, then SIGKILL any remaining. Use `signal.NotifyContext()` with `context.Cause()` to detect which signal triggered shutdown.

### 8. Entry point integration
In `cmd/wire/main.go`: after loading config, create a `process.Manager`, call `Start(ctx)`. Block until context is cancelled. Call `Stop()` on shutdown.

## Constraints
- `go build ./...` must pass.
- `go test ./...` must pass.
- Do not modify files outside the Modifies/Creates list unless strictly required.
- Do not use third-party process supervision libraries. `os/exec` + goroutines is sufficient.
- The manager must be safe for concurrent access (multiple goroutines calling `Healthy`, `Addr`, `Swap`).

## Failure Modes
- **Port conflict**: auto-assigned port is taken between `net.Listen` close and llama-server start. Detection: health check fails, process restarts on a new port. Mitigation: retry with a new port on startup failure.
- **Zombie processes on unclean shutdown**: wire crashes without sending SIGTERM. Detection: stale llama-server processes on next start. Mitigation: not handled in this WU — document as known limitation.
- **Restart loop**: llama-server crashes repeatedly (bad model, OOM). Detection: max retry count exceeded, logged as error. Manager stops retrying for that backend.
- **Swap during active request**: request in flight when backend restarts gets a connection error. Detection: gateway returns 502. Mitigation: handled in wu-03 (gateway retries or returns 503).

# Route requests through HTTP gateway

## Outcome
Wire exposes a single HTTP port that accepts OpenAI-compatible API requests and routes them to the correct backend based on the `model` field in the request body. Responses are streamed without buffering. `GET /v1/models` returns a merged list from all backends.

## Values
1. Low memory — stream request and response bodies without buffering entire payloads.
2. Transparent proxy — apps cannot distinguish wire from a direct llama-server connection (same API, same SSE format).
3. Correct routing — wrong or missing model name returns a clear error, not a silent misroute.

## Context
- `internal/config/config.go` — `Config` with `Listen` address and `Backends` map. Each backend has a name (map key) that is also used for routing.
- `internal/process/manager.go` — `Manager` provides `Addr(name) (string, bool)` to get backend URLs and `Healthy(name) bool` for health checks.
- The `model` field in OpenAI API requests (`/v1/chat/completions`, `/v1/embeddings`, `/v1/completions`) identifies which backend to route to.
- Routing rule: match the `model` value against backend names. If a backend has a `Model` config field, also match against that value (e.g., model="qwen3-coder-30b" matches a backend named "chat" with `Model: "Qwen/Qwen3-Coder-30B-A3B-Instruct-GGUF:Q4_K_M"`). The backend name is the short alias.
- llama-server sets the model name in responses to the filename stem of the loaded model. Wire must rewrite this in responses to match the backend name the client used.
- This project uses Go 1.26. Use `httputil.ReverseProxy` with `Rewrite` (not `Director` — deprecated). Use `log/slog` for logging. Use `errors.AsType[T]` where applicable.

## Creates
- `internal/gateway/gateway.go` — HTTP server with routing logic.
- `internal/gateway/gateway_test.go` — tests for routing and model listing.
- `internal/gateway/route.go` — model-name to backend resolution.

## Modifies
- `cmd/wire/main.go` — start the gateway after the process manager.

## Requirements

### 1. Gateway type
```go
type Gateway struct { ... }

func New(cfg *config.Config, mgr *process.Manager, log *slog.Logger) *Gateway
func (g *Gateway) ListenAndServe(ctx context.Context) error
```

### 2. Route table
Build a route table from config at startup:
- For each backend, register the backend name as a valid model alias.
- For managed backends, also register the HuggingFace ref and any reasonable short forms (e.g., for `Qwen/Qwen3-Coder-30B-A3B-Instruct-GGUF:Q4_K_M`, also register the filename stem without extension and quantization).
- Route resolution: given a model string from a request, find the matching backend name. Return an error if no match or ambiguous.

### 3. Request routing
For `POST /v1/chat/completions`, `POST /v1/embeddings`, `POST /v1/completions`, `POST /v1/rerank`:
1. Read only the `model` field from the request body without consuming the entire body. Use `json.NewDecoder` on a `io.TeeReader` to capture the bytes read so far, then reconstruct the full body by concatenating captured bytes with the remaining unread body. This avoids buffering the entire request.
2. Resolve the model to a backend name.
3. If the backend is unhealthy, return HTTP 503 with `{"error": {"message": "backend unavailable", "type": "server_error"}}`.
4. Proxy the request to the backend URL using `httputil.ReverseProxy` with `Rewrite`.
5. For streaming responses (SSE), ensure `Flush` is called on each chunk. Set `FlushInterval: -1` on the `ReverseProxy` to flush immediately.

### 4. /v1/models endpoint
`GET /v1/models` returns a merged list from all backends:
- For managed backends: query `GET /v1/models` on the backend's internal URL.
- For external backends: query their URL's `/v1/models` (best-effort, skip on error).
- Merge results. Each model entry should include the backend name as an alias.
- Response format matches OpenAI: `{"object": "list", "data": [{"id": "...", "object": "model", ...}]}`.

### 5. Health endpoint
`GET /health` returns 200 with `{"status": "ok"}` if at least one backend is healthy. Returns 503 with `{"status": "degraded"}` otherwise.

### 6. Error responses
All errors return JSON in OpenAI error format:
```json
{"error": {"message": "...", "type": "...", "code": "..."}}
```
- Unknown model: 400, type `invalid_request_error`.
- Backend unhealthy: 503, type `server_error`.
- No backends configured: 500, type `server_error`.

### 7. Streaming without buffering
- Set `ReverseProxy.FlushInterval = -1` for immediate flushing.
- Do not set `ReverseProxy.ModifyResponse` to buffer the response body.
- SSE responses (`text/event-stream`) must be streamed chunk-by-chunk to the client.
- Non-SSE responses are also streamed (default `ReverseProxy` behavior).

### 8. Entry point integration
In `cmd/wire/main.go`: after starting the process manager, create the gateway and call `ListenAndServe(ctx)`. The gateway's HTTP server should shut down gracefully on context cancellation using `http.Server.Shutdown()`.

## Constraints
- `go build ./...` must pass.
- `go test ./...` must pass.
- Do not modify files outside the Modifies/Creates list unless strictly required.
- Do not buffer entire request or response bodies in memory. The proxy must handle large streaming responses without growing memory.
- Do not import third-party HTTP frameworks. `net/http` + `httputil` is sufficient.

## Failure Modes
- **Model field extraction fails on malformed JSON**: request body isn't valid JSON. Detection: return 400 with clear error message. Don't proxy garbage.
- **Request body consumed by model extraction**: `json.Decoder` reads past the model field, downstream gets truncated body. Detection: test with large request bodies. Mitigation: `TeeReader` captures all bytes read.
- **SSE not flushed**: client sees nothing until response completes. Detection: test with streaming backend mock. Mitigation: `FlushInterval: -1`.
- **Backend returns non-200 during swap**: gateway proxies the error response. This is correct — the client sees the real error.

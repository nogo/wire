# Add Manager.Reload for selective restart

## Outcome
When the manager receives a new config, it compares model parameters for each currently running process. Models whose params changed are drained and restarted with the new params. Models not currently loaded simply pick up new params on next `LoadOrGet`. The gateway's config reference is also updated so new requests use the new config for model matching.

## Values
1. Availability — in-flight requests complete before a model restarts. No request is dropped.
2. Correctness — only models with actual param changes restart. Unchanged models keep serving.
3. Safety — global config fields that cannot hot-reload (listen address) are logged as warnings, not applied.

## Requirements

### 1. Manager.Reload method
```go
func (m *Manager) Reload(newCfg *config.Config)
```
- Acquires `m.mu` write lock.
- Updates `m.cfg` to `newCfg`.
- For each entry in `m.procs` that is `stateHealthy` or `stateLoading`:
  - Look up the model's new params via `newCfg.MatchModel(modelName)`.
  - If the model no longer matches any pattern: drain it (cancel context, wait for supervisor exit, delete from procs).
  - If params differ from `ps.params`: drain it, then start a new supervisor with the new params. Preserve `isWarmup` flag.
  - If params are unchanged: no action.
- For new warmup entries not currently in `m.procs`: start supervisor.
- For warmup entries removed from the new config that are currently running as warmup: drain them.
- Log each action at `slog.Info` level: "reloading model" / "draining removed model" / "starting new warmup model".

### 2. Param comparison
Compare `ModelParams` structs using `==` (all fields are comparable: ints, string, and `[]string`). Note: `[]string` (Extra) is not comparable with `==`. Use `reflect.DeepEqual` or a helper function that compares each field. Prefer a dedicated `Equal` method on `ModelParams` to avoid reflect.

### 3. Gateway config update
Add a method to Gateway:
```go
func (g *Gateway) UpdateConfig(cfg *config.Config)
```
- Stores `cfg` atomically (use `sync.RWMutex` or `atomic.Pointer[config.Config]`).
- `handleRoute` reads config through the lock/atomic load.
- This ensures new requests use updated model patterns and params for the context window guard.

### 4. Drain mechanics
Reuse the same pattern as `evictIfNeeded`: set state to `stateDraining`, call `ps.cancel()`, `ps.wg.Wait()`, delete from procs. The drain must happen with `m.mu` temporarily released (same as eviction) to avoid deadlock with the supervisor goroutine.

### 5. Tests
- Test that `Reload` with changed params restarts the affected model (mock process exits, new one starts).
- Test that `Reload` with unchanged params does NOT restart the model.
- Test that `Reload` with a removed model drains it.
- Test that `Reload` with a new warmup model starts it.

## Constraints
- `mise run check` must pass.
- Do not modify files outside the Modifies list.
- `Reload` must not block indefinitely — if a model refuses to drain, it should respect the existing 10s `WaitDelay` on the process.
- Never restart a model that has in-flight requests without draining first. The drain waits for the supervisor to exit, which waits for the process, which has a 10s graceful shutdown window.

## Failure Modes
- **Deadlock on m.mu**: supervisor goroutine holds ps.mu and tries to read m.mu while Reload holds m.mu write lock. Detection: test with concurrent LoadOrGet and Reload. Mitigation: release m.mu before waiting on ps.wg (same pattern as eviction).
- **Stale config in gateway**: handleRoute reads old config after Reload updates manager. Detection: test that Reload updates both manager and gateway config.
- **Restart storm**: all models match a changed global default. Detection: log review showing which models actually changed params.
- **Extra field comparison**: `[]string{"a"}` vs `[]string{"a"}` with `==` panics. Detection: test with Extra field set.

# Add CLI commands

## Outcome
The `wire` binary supports subcommands: `wire start` (run gateway + process manager in foreground), `wire stop` (stop a running instance), `wire status` (show backends and health), `wire swap <backend> <model>` (hot-swap a model). All commands work without an admin API — `start` runs in foreground, `stop` sends SIGTERM to the PID, `status` queries the gateway's health and models endpoints, `swap` updates config and signals a reload.

## Values
1. Simplicity — no admin API, no daemon protocol. The CLI uses signals and the public API.
2. Ergonomic — commands are short and obvious. Output is human-readable.
3. No surprises — `wire start` blocks in foreground (systemd manages daemonization).

## Context
- `cmd/wire/main.go` — current entry point that loads config and starts process manager + gateway.
- `internal/config/config.go` — `Config` type with `Load()` function. Config path is `~/.config/wire/config.yaml` or `WIRE_CONFIG`.
- `internal/process/manager.go` — `Manager` with `Start()`, `Stop()`, `Swap()`, `Healthy()`, `Addr()`.
- `internal/gateway/gateway.go` — `Gateway` with `ListenAndServe()`.
- The gateway exposes `GET /health` and `GET /v1/models` on the configured listen address.
- This project uses Go 1.26. Use `signal.NotifyContext()` with `context.Cause()`. Use `log/slog`. No third-party CLI frameworks — use standard `flag` package or bare `os.Args` subcommand dispatch.

## Creates
- `internal/cli/cli.go` — subcommand dispatch and implementations.
- `internal/cli/cli_test.go` — tests for argument parsing.

## Modifies
- `cmd/wire/main.go` — delegate to CLI dispatch instead of directly starting services.

## Requirements

### 1. Subcommand dispatch
Parse `os.Args[1]` as the subcommand. Supported commands:
- `start` — run the gateway in foreground.
- `stop` — stop a running instance.
- `status` — show backend status.
- `swap <backend> <model>` — hot-swap a backend's model.
- No subcommand or `help` or `--help` — print usage.

No third-party CLI library. A simple switch statement on `os.Args[1]` is sufficient.

### 2. `wire start`
1. Load config.
2. Write PID to `$XDG_RUNTIME_DIR/wire.pid` (fall back to `/tmp/wire.pid`).
3. Create process manager, start all backends.
4. Create gateway, start listening.
5. Log `"wire ready"` with listen address when all healthy backends are up.
6. Block until SIGTERM/SIGINT. Log which signal caused shutdown via `context.Cause()`.
7. Graceful shutdown: stop gateway (drain connections, 5s timeout), then stop process manager.
8. Remove PID file on exit.

### 3. `wire stop`
1. Read PID from the PID file.
2. Send SIGTERM to that PID.
3. Wait up to 10 seconds for the process to exit (poll `/proc/<pid>` or `kill -0`).
4. If still running, send SIGKILL.
5. Print confirmation.

### 4. `wire status`
1. Load config to get the listen address.
2. `GET http://<listen>/health` — print overall status.
3. `GET http://<listen>/v1/models` — print each model with its backend name and status.
4. If the gateway isn't running (connection refused), print "wire is not running" and exit 1.
5. Output format: plain text, one line per backend. Example:
   ```
   wire: healthy (http://localhost:8080)
   chat:      qwen3-coder-30b    healthy
   embedding: bge-m3             healthy
   ```

### 5. `wire swap <backend> <model>`
1. Load config.
2. Validate that `<backend>` exists and is a managed backend. External backends cannot be swapped (print error).
3. Update the config file: change the backend's `model` field to `<model>`.
4. Send SIGHUP to the running wire process (read PID from PID file).
5. Wire's `start` command must handle SIGHUP: reload config from disk, call `manager.Swap()` for changed backends.
6. Print confirmation after sending the signal. The actual swap happens asynchronously — user can run `wire status` to check progress.

### 6. SIGHUP reload handler
In the `start` command's main loop, listen for SIGHUP in addition to SIGTERM/SIGINT. On SIGHUP:
1. Reload config from disk.
2. For each backend: if the model changed, call `manager.Swap(ctx, name, newModel)`.
3. Log what changed.
4. Do not restart the gateway or change the listen address (requires a full restart).

### 7. Usage output
```
Usage: wire <command> [arguments]

Commands:
  start               Start the gateway (foreground)
  stop                Stop the running gateway
  status              Show backend status
  swap <backend> <model>  Hot-swap a backend's model

Environment:
  WIRE_CONFIG         Config file path (default: ~/.config/wire/config.yaml)
```

## Constraints
- `go build ./...` must pass.
- `go test ./...` must pass.
- Do not modify files outside the Modifies/Creates list unless strictly required.
- No third-party CLI frameworks. Standard library only.
- PID file management must be race-safe: use `os.OpenFile` with `O_CREATE|O_EXCL` to detect another running instance.

## Failure Modes
- **Stale PID file**: wire crashed without cleanup, PID file points to dead or wrong process. Detection: `wire start` checks if PID is alive and belongs to a wire process before refusing to start. Mitigation: if PID is dead, remove stale file and proceed.
- **SIGHUP during swap**: a swap is in progress when another SIGHUP arrives. Detection: log a warning. Mitigation: ignore SIGHUP while a swap is in progress (simple mutex).
- **Config file write race**: `wire swap` writes config while `wire start` reads it on SIGHUP. Mitigation: write to a temp file, then atomic rename.

# Add speculative decoding config fields

## Outcome

Users can enable n-gram speculative decoding for any model by adding `spec_type`, `draft_max`, `draft_min`, `spec_ngram_n`, and `spec_ngram_m` fields to their model config. Wire passes these as llama-server CLI flags. Models configured with `spec_type: ngram-mod` generate tokens faster without additional VRAM or a draft model. Invalid `spec_type` values are rejected at config load time.

## Values

1. Correctness — flags must map exactly to llama-server's CLI interface.
2. Zero surprises — omitted or zero-valued fields produce no flags. Existing configs are unaffected.
3. Fail early — invalid spec_type is caught at startup, not at llama-server launch.

## Requirements

### 1. ModelParams fields

Add five fields to `ModelParams`:

```go
SpecType  string `yaml:"spec_type"`   // speculative decoding type
DraftMax  int    `yaml:"draft_max"`   // max tokens to draft
DraftMin  int    `yaml:"draft_min"`   // min tokens to draft
SpecNgramN int   `yaml:"spec_ngram_n"` // lookup n-gram size
SpecNgramM int   `yaml:"spec_ngram_m"` // draft m-gram size
```

All default to zero/empty (disabled). No changes to `applyDefaults`.

### 2. Validation

In `validate()`, if any model pattern has a non-empty `SpecType`, it must be one of: `ngram-simple`, `ngram-mod`, `ngram-cache`, `ngram-map-k`, `ngram-map-k4v`. Return a descriptive error naming the invalid value and the pattern it belongs to.

`DraftMax`, `DraftMin`, `SpecNgramN`, `SpecNgramM` are not validated beyond being non-negative (zero means omit). Negative values are not possible with `int` from YAML unless explicitly set — no guard needed.

### 3. Flag generation in buildArgs

After the existing `Pooling` block and before `return append(args, params.Extra...)`, append flags conditionally:

- `params.SpecType != ""` → `--spec-type`, `params.SpecType`
- `params.DraftMax > 0` → `--draft-max`, `strconv.Itoa(params.DraftMax)`
- `params.DraftMin > 0` → `--draft-min`, `strconv.Itoa(params.DraftMin)`
- `params.SpecNgramN > 0` → `--spec-ngram-size-n`, `strconv.Itoa(params.SpecNgramN)`
- `params.SpecNgramM > 0` → `--spec-ngram-size-m`, `strconv.Itoa(params.SpecNgramM)`

`Extra` must remain last (user escape hatch).

### 4. Tests

**Config tests:**
- `TestLoad_SpecType`: YAML with `spec_type: ngram-mod`, `draft_max: 16` parses correctly.
- `TestLoad_SpecTypeInvalid`: YAML with `spec_type: unknown` returns error.
- `TestLoad_SpecTypeEmpty`: No spec fields → loads without error, fields are zero/empty.

**buildArgs tests:**
- `TestBuildArgs_speculative`: All five fields set → correct flags in output.
- `TestBuildArgs_speculative_empty`: All fields zero/empty → no spec flags in output.
- `TestBuildArgs_speculative_partial`: Only `spec_type` set → only `--spec-type` flag.

## Constraints

- `mise run check` must pass.
- Do not modify files outside the Modifies list.
- Do not add `--model-draft` support — draft model pairing requires VRAM-aware scheduling (separate roadmap item).
- `Extra` field must remain the last item appended to args (it's the user's escape hatch for flags Wire doesn't know about).
- No new dependencies.

## Failure Modes

- **Wrong flag names**: llama-server rejects unknown flags at startup. Detection: start Wire with spec config, check llama-server stderr for flag errors.
- **Spec flags before Extra**: User overrides in `Extra` would be shadowed. Detection: `TestBuildArgs` verifies `Extra` is last.
- **Missing validation**: Invalid spec_type passes config load, llama-server fails at runtime with unclear error. Detection: `TestLoad_SpecTypeInvalid` catches this.

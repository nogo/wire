# Serve live monitor dashboard via websocket

## Outcome
When `monitor: true` is set in config, `GET /monitor` serves an embedded HTML dashboard and `GET /monitor/ws` upgrades to a websocket that streams live telemetry. The page shows GPU hardware metrics (utilization, VRAM, temperature, power), backend status, KV cache usage, slot activity, throughput, and a scrolling request log — all updating in real-time. When `monitor` is false (default), these routes do not exist.

## Values
1. Zero-install experience — single page, no build step, no external assets. Everything is `go:embed`.
2. Real-time fidelity — websocket pushes updates as they happen; no browser-side polling.
3. Opt-in only — when disabled, zero overhead: no hub goroutine, no metrics polling, no routes registered.

## Requirements

### 1. Config field
Add to `Config`:
```go
Monitor bool `yaml:"monitor"`
```
Default is `false` (zero value). No validation needed — boolean.

### 2. Hub lifecycle in CLI
In `runStart()`, after creating the manager and before creating the gateway:
```go
var hub *monitor.Hub
if cfg.Monitor {
    hub = monitor.NewHub(mgr)
    hub.Start(bgCtx)
    defer hub.Stop()
}
gw := gateway.New(cfg, mgr, hub, slog.Default())
```
`hub` is nil when monitoring is disabled. Gateway must handle nil hub gracefully (don't register routes).

### 3. Gateway integration
Modify `gateway.New` / `newGateway` to accept an optional `*monitor.Hub`. When non-nil, register:
- `GET /monitor` — serves the embedded HTML page.
- `GET /monitor/ws` — websocket upgrade handler.

When hub is nil, these routes are not registered. No conditional checks in the handlers — the routes simply don't exist.

### 4. Websocket handler
In `internal/monitor/websocket.go`:
1. Accept the HTTP request, upgrade to websocket using `nhooyr.io/websocket.Accept()`. Set `InsecureSkipVerify: true` for origin check (local tool, not a public API).
2. Send the current snapshot as the first message (JSON, `type: "snapshot"`).
3. Subscribe to the hub via `hub.Subscribe()`.
4. Loop: read from subscription channel, marshal to JSON, write to websocket.
5. On websocket close or context cancellation: unsubscribe and return.
6. Ignore all incoming messages from the client (read-only protocol). Start a discard goroutine that reads and discards client messages to detect close frames.

JSON wire format for each message type:

**Snapshot** (sent once on connect):
```json
{
  "type": "snapshot",
  "backends": {
    "<name>": {
      "model": "...",
      "status": "healthy|unhealthy|loading",
      "pid": 1234,
      "port": 41023,
      "uptime_sec": 15120,
      "restarts": 0
    }
  },
  "gpus": [
    {
      "index": 1,
      "name": "AMD Radeon 890M Graphics",
      "busy_pct": 97,
      "vram_total": 51539607552,
      "vram_used": 17435750400,
      "temp_c": 80.0,
      "power_w": 35.0
    }
  ]
}
```
The `gpus` array is empty if no GPUs were discovered. The dashboard hides the GPU section entirely when empty.

**GPU metrics** (periodic, per poll tick):
```json
{
  "type": "gpu",
  "gpus": [
    {
      "index": 1,
      "name": "AMD Radeon 890M Graphics",
      "busy_pct": 97,
      "vram_total": 51539607552,
      "vram_used": 17435750400,
      "temp_c": 80.0,
      "power_w": 35.0
    }
  ]
}
```

**Metrics** (periodic, per backend):
```json
{
  "type": "metrics",
  "backend": "<name>",
  "kv_cache_pct": 62.1,
  "slots_busy": 2,
  "slots_total": 4,
  "queue_depth": 1,
  "gen_tok_s": 14.2,
  "prompt_tok_s": 1204.0,
  "slots": [
    {"id": 0, "state": "generating", "tokens": 284, "ctx_used": 3841},
    {"id": 1, "state": "idle", "tokens": 0, "ctx_used": 0}
  ]
}
```

**Event** (per stderr parse):
```json
{
  "type": "event",
  "backend": "<name>",
  "kind": "prompt_eval|gen_eval|slot_assign|slot_release|model_load|vram_alloc|error|raw",
  "slot": 0,
  "tokens": 1847,
  "tok_s": 12961.4,
  "duration_ms": 142.5,
  "message": "..."
}
```

**State change** (health transition, swap):
```json
{
  "type": "state",
  "backend": "<name>",
  "status": "healthy|unhealthy|swapping",
  "model": "..."
}
```

### 5. HTML dashboard
Single file `internal/monitor/page.html`. Embedded via `go:embed` in `page.go`. Requirements:

**Layout:**
- Header bar with "wire monitor" title and connection status indicator (green dot = connected, red = disconnected).
- GPU section (hidden when no GPUs discovered). One card per GPU containing:
  - GPU name and index.
  - Utilization bar — horizontal fill with percentage label.
  - VRAM bar — horizontal fill showing used/total (e.g., "16.2 / 48.0 GiB").
  - Temperature — numeric with color coding: green <70C, yellow 70–85C, red >85C.
  - Power draw — numeric in watts.
- Backend cards, one per backend. Each card contains:
  - Name, model (truncated with tooltip), status badge, PID, uptime.
  - KV cache bar — horizontal bar fill with percentage label. This is the most prominent visual element.
  - Slot table — rows for each slot showing state, tokens generated, context used.
  - Throughput numbers — generation tok/s and prompt tok/s.
- Request log — scrolling list at the bottom showing parsed stderr events (prompt_eval and gen_eval). Most recent at top. Cap at 100 entries, discard oldest. Each entry shows: timestamp, backend/slot, tokens, tok/s.

**Behavior:**
- Connect to `ws://<same-host>/monitor/ws` on load.
- On snapshot message: render GPU cards (if `gpus` non-empty) and all backend cards.
- On gpu message: update GPU card gauges (utilization bar, VRAM bar, temperature, power).
- On metrics message: update the matching backend card's gauges, slots, throughput.
- On event message: if `prompt_eval` or `gen_eval`, prepend to request log. Update slot table if `slot_assign` or `slot_release`.
- On state message: update backend status badge, flash on transition.
- On disconnect: show red indicator, attempt reconnect every 3 seconds.
- Auto-reconnect sends no special handshake — the server sends a fresh snapshot on each new connection.

**Style:**
- Dark theme (dark background, light text — standard for monitoring tools).
- Monospace font for numbers and the request log.
- Minimal, functional. No animations except the KV cache bar fill transition.
- Responsive: works on a narrow terminal browser or a full-width monitor.
- No external fonts, icons, or assets. Pure CSS.

### 6. Page handler
In `internal/monitor/page.go`:
```go
//go:embed page.html
var pageHTML []byte

func HandlePage(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "text/html; charset=utf-8")
    w.Write(pageHTML)
}
```

## Constraints
- `go build ./...` must pass.
- `go test ./...` must pass.
- Do not modify files outside the Creates/Modifies list unless strictly required.
- The HTML file must be fully self-contained — no external CDN links, no fetch() to third-party URLs, no external fonts.
- The websocket is server→client only. The handler must not act on client messages beyond detecting close frames.
- When `monitor: false` (default), the hub must not be created, no goroutines must be spawned, and `/monitor` routes must not be registered. Zero overhead when disabled.
- Use `nhooyr.io/websocket`, not `gorilla/websocket`.

## Failure Modes
- **Websocket connection leak**: client disconnects without close frame (browser crash, network drop). Detection: the discard-read goroutine will get an error, triggering cleanup. Test: close the `httptest.Server` connection mid-stream, verify unsubscribe is called.
- **Hub stops while clients connected**: `hub.Stop()` closes subscriber channels. Websocket handler must detect closed channel and close the websocket gracefully. Detection: test hub stop with active subscriber.
- **Large snapshot on many backends**: snapshot JSON grows with backend count. With 2-4 backends this is trivial (<1KB). Not a real concern at wire's scale, but the handler should set a write deadline (10s) to avoid hanging on a blocked write.
- **Stale browser tab**: tab left open for days, websocket stays connected, events accumulate. Detection: write deadline on websocket prevents stuck connections. The browser's 100-entry request log cap prevents DOM bloat.
- **HTML embed missing**: `go:embed` fails at compile time if the file doesn't exist. Detection: `go build` fails. No runtime risk.

# [gate] Config hot-reload integration tests

## Outcome
Integration tests verify the full hot-reload path: config file change → watcher detects → manager restarts affected model → gateway uses new config. Tests cover the happy path (param change triggers restart), no-op path (unchanged config), and safety path (invalid config is rejected).

## Values
1. Confidence — these tests exercise the assembled path end-to-end, not individual units.
2. Specificity — failure messages identify exactly which step broke.

## Context
- `internal/config/watch.go` — `Watch()` function.
- `internal/config/config.go` — `Load()`, `Path()`, `Config`, `ModelParams`.
- `internal/process/manager.go` — `Manager`, `Reload()`, `startSupervisor()`, mock patterns from existing tests.
- `internal/gateway/gateway.go` — `Gateway`, `UpdateConfig()`.
- `internal/cli/cli.go` — `runUp()` wiring.

## Creates
- `internal/integration_test.go` — integration tests for the hot-reload flow (build-tagged if needed, or using test helpers that mock the process layer).

## Modifies
None.

## Requirements

### 1. Test: param change triggers model restart
- Start a manager with a mock cmdBuilder and a model loaded with `Context: 4096`.
- Write a new config file with `Context: 8192` for the same model.
- Call `Manager.Reload()` with the new config.
- Assert the old process was drained (supervisor exited).
- Assert a new process was started with the updated params.

### 2. Test: unchanged config is a no-op
- Start a manager with a model loaded.
- Call `Reload()` with an identical config.
- Assert no process was restarted (no drain, no new supervisor).

### 3. Test: invalid config does not reach manager
- Start a `config.Watch()` on a temp directory.
- Write invalid YAML to the config file.
- Assert nothing is received on the watch channel within a reasonable timeout.
- Write valid YAML.
- Assert the valid config IS received.

### 4. Test: gateway uses updated config
- Create a gateway with a config that matches model "org/model-a".
- Call `UpdateConfig()` with a config that also matches "org/model-b".
- Send a request for "org/model-b".
- Assert it routes successfully (not 404).

## Constraints
- `mise run check` must pass.
- Tests must not start real llama-server processes — use the mock cmdBuilder pattern from existing tests.
- No long-lived processes in tests (L-001).
- Tests must clean up temp files and directories.

## Failure Modes
- **Flaky timing**: watcher debounce + filesystem event delivery can vary. Use generous timeouts (5s) with `time.After` in select, not `time.Sleep`.
- **Temp dir cleanup**: leaked temp dirs on test failure. Mitigation: `t.TempDir()` handles cleanup automatically.

## Verification
```bash
mise run check
go test ./internal/ -run TestHotReload -v
```

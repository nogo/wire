# Add config file watcher

## Outcome
Wire detects changes to config.yaml while running and emits validated, parsed `*config.Config` values on a channel. Invalid configs are logged and discarded — the running config is never replaced with a broken one. Editor write-rename patterns (vim, sed -i) do not cause spurious reloads.

## Values
1. Safety — invalid config never reaches the manager. A typo must not kill a running setup.
2. Reliability — debounce handles editor temp-file dances without missing real changes.
3. Minimal dependencies — use `fsnotify/fsnotify` (widely used, maintained, BSD license).

## Context
- `internal/config/config.go` — `Load()`, `Path()`, `Config` struct. The watcher reuses `Load()` for parsing and validation.
- `go.mod` — current deps are yaml.v3 and nhooyr.io/websocket. `fsnotify` will be the third.

## Creates
- `internal/config/watch.go` — `Watch` function and watcher loop.
- `internal/config/watch_test.go` — tests for debounce, invalid config rejection, and successful reload.

## Modifies
- `go.mod` — add `github.com/fsnotify/fsnotify` dependency.
- `go.sum` — updated by `go mod tidy`.

## Requirements

### 1. Watch function
```go
func Watch(ctx context.Context, log *slog.Logger) (<-chan *Config, error)
```
- Resolves config path via `Path()`.
- Creates an fsnotify watcher on the **directory** containing the config file (not the file itself — editors that do write-rename delete the inode, breaking file-level watches).
- Returns a channel that emits `*Config` values whenever the config file changes and parses+validates successfully.
- The goroutine exits and closes the channel when `ctx` is cancelled.

### 2. Debounce
After receiving a filesystem event for the config file, wait 500ms before reading. If more events arrive during the wait, reset the timer. This handles editor write patterns (write temp → rename → delete old) without multiple reloads.

### 3. Reload logic
- Call `Load()` to parse and validate.
- On success: send the new `*Config` on the channel (non-blocking; drop if receiver is slow — log a warning).
- On failure: log the error at `slog.Error` level with the parse/validation error. Do not send anything on the channel.

### 4. Event filtering
Only react to events where the filename matches the config file basename. Ignore events for other files in the same directory.

## Constraints
- `mise run check` must pass.
- Do not modify files outside the Modifies/Creates lists.
- The watcher goroutine must not leak — it must exit when ctx is cancelled and close the fsnotify watcher.
- Channel buffer size: 1. Non-blocking send with drop-and-warn on full.

## Failure Modes
- **Watcher on file instead of directory**: editor rename deletes the inode → no more events after first edit. Detection: test that simulates write-rename pattern.
- **No debounce**: vim's multi-step save triggers 2-3 reloads per edit. Detection: test that sends multiple events in quick succession and asserts only one config is emitted.
- **Goroutine leak**: watcher goroutine outlives context. Detection: test cancels context and asserts channel is closed.
- **Invalid config sent on channel**: bad YAML reaches the manager → crash. Detection: test writes invalid YAML and asserts nothing is received on channel.

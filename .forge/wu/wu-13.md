# Add context window guard to gateway

## Outcome

Requests whose estimated token count exceeds the model's context window (`n_ctx`) are rejected with a clear error before reaching llama-server. No silent truncation. The error message includes the estimated token count and the context limit, enabling callers to retry with shorter input. When monitoring is disabled (hub is nil) or n_ctx is unknown, the guard is skipped and requests pass through unchanged.

## Values

1. Safety — prevent silent truncation, the worst failure mode for agents and RAG pipelines.
2. No false rejections — the heuristic must be permissive. A request that fits should never be blocked.
3. Zero overhead for normal requests — guard adds no latency when the request is well within limits.

## Requirements

### 1. Hub NCtx method

Add to `Hub`:

```go
func (h *Hub) NCtx(model string) int
```

Returns the `n_ctx` value for the named model from the last poll. Implementation: read `h.metrics[model]` under `h.mu.RLock()`. If the model exists and has at least one slot, return `Slots[0].NCtx`. Otherwise return 0 (meaning "unknown, skip guard").

### 2. Store hub reference in Gateway

Add `hub *monitor.Hub` field to `Gateway` struct. Set it in `newGateway()` from the existing `hub` parameter. The hub may be nil (monitor disabled).

### 3. Token estimation

Add a package-level function:

```go
func estimateTokens(body []byte) int
```

Parses the JSON body to extract text content from `messages[].content` fields (for chat endpoints) or `input` field (for embeddings). Sums the character count of all text content and divides by 4 (standard English heuristic). Returns 0 on parse error (guard skipped).

This function does NOT need to handle every edge case (tool calls, image URLs, etc.). It estimates from text content only. Under-estimation is acceptable; the 90% threshold provides margin.

### 4. Guard check in handleRoute

After `LoadOrGet` succeeds and before affinity assignment, insert the guard:

1. Skip if `g.hub == nil` (monitor disabled).
2. Call `g.hub.NCtx(payload.Model)`. Skip if result is 0.
3. Call `estimateTokens` on the captured request body. Skip if result is 0.
4. If `estimatedTokens > nCtx * 9 / 10` (integer arithmetic, avoids float), return error:
   - HTTP 400
   - Type: `invalid_request_error`
   - Code: `context_length_exceeded`
   - Message: `"estimated %d tokens exceeds context window of %d (n_ctx)"` with actual values.
5. Otherwise, continue to affinity assignment.

The body bytes are already available from the TeeReader capture (`captured` buffer, line 98). Re-read them for estimation; this does not consume the body (it's already been captured).

### 5. Tests

**Hub tests:**
- `TestHub_NCtx`: Populate `h.metrics` manually with a BackendMetrics containing Slots with NCtx=4096. Assert `NCtx("model")` returns 4096.
- `TestHub_NCtx_unknown`: Assert `NCtx("nonexistent")` returns 0.
- `TestHub_NCtx_noSlots`: BackendMetrics with empty Slots slice → returns 0.

**Gateway tests:**
- `TestHandleRoute_contextGuard_reject`: Mock hub returning NCtx=100. Send request with messages totaling >360 chars (estimated 90+ tokens, exceeding 90% of 100). Assert HTTP 400 with `context_length_exceeded` code.
- `TestHandleRoute_contextGuard_pass`: Same setup, request with short messages. Assert request reaches backend (HTTP 200).
- `TestHandleRoute_contextGuard_noHub`: Hub is nil. Large request passes through unchanged.
- `TestEstimateTokens`: Unit test the estimation function directly with known inputs.

## Constraints

- `mise run check` must pass.
- Do not modify files outside the Modifies list.
- Guard must not add measurable latency to requests that pass. The JSON parse for estimation reuses the already-captured body bytes — no extra I/O.
- Guard is best-effort: if estimation fails or n_ctx is unknown, the request passes through. Never block a request due to guard malfunction.
- No new dependencies.
- The `backendManager` interface in gateway.go must NOT change. Hub access is separate from process management.

## Failure Modes

- **Over-estimation rejects valid requests**: chars/4 over-counts for languages with longer words or whitespace-heavy prompts. Mitigated by 90% threshold. Detection: test with known token counts.
- **Under-estimation passes oversized requests**: chars/4 under-counts for CJK or code. Acceptable — the guard is a safety net, not a guarantee. llama-server still handles these.
- **Hub returns stale n_ctx**: If model was just loaded and hub hasn't polled yet, n_ctx is 0 → guard skipped → request passes. Acceptable for first-request-after-load; hub polls every 1s.
- **Guard blocks embeddings incorrectly**: Embedding requests have `input` not `messages`. `estimateTokens` must handle both formats. Detection: test with embedding request body.

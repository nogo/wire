# Wire config watcher into CLI startup

## Outcome
When `wire up` starts, it watches config.yaml for changes. On valid config change, the manager reloads affected processes and the gateway updates its config reference. Users see a log line for each reload ("config reloaded", "reloading model X", etc.) and for each rejected config ("config reload failed: ..."). No restart of `wire up` is needed to apply config changes.

## Values
1. Seamless operation — reload happens in the background, no disruption to unaffected models.
2. Observability — every reload (success or failure) is logged clearly.

## Context
- `internal/cli/cli.go` — `runUp()` (line 58-112) is the startup entrypoint. Config is loaded once, manager and gateway are created, then the main loop waits for shutdown.
- `internal/config/watch.go` — `Watch()` function from wu-15.
- `internal/process/manager.go` — `Manager.Reload()` from wu-16.
- `internal/gateway/gateway.go` — `Gateway.UpdateConfig()` from wu-16.

## Creates
None.

## Modifies
- `internal/cli/cli.go`

## Requirements

### 1. Start watcher
After `config.Load()` succeeds and before entering the main select loop, call `config.Watch(bgCtx, slog.Default())`. If Watch returns an error (e.g., fsnotify init failure), log it as a warning and continue without watching — the watcher is best-effort, not required for operation.

### 2. Consume reload channel
Add a case to the main `select` loop in `runUp()` that reads from the watcher channel:
```go
case newCfg := <-reloadCh:
    slog.Info("config reloaded")
    mgr.Reload(newCfg)
    gw.UpdateConfig(newCfg)
```
If the watcher was not started (error case), use a nil channel so the select case is never triggered.

### 3. Global field warnings
Before calling `mgr.Reload`, compare `listen` and `monitor` fields. If they differ from the running config, log a warning: "listen address change requires restart" / "monitor setting change requires restart". Do not apply these changes.

### 4. MaxModels update
`max_models` can be updated in-memory safely. Pass it through to the manager via `Reload` (which already receives the full new config). The manager should respect the new `MaxModels` for future eviction decisions.

## Constraints
- `mise run check` must pass.
- Do not modify files outside the Modifies list.
- The watcher goroutine must be cancelled by `bgCtx` cancellation during shutdown. No goroutine leak.

## Failure Modes
- **Nil channel panic**: if Watch failed and reloadCh is nil, a select on nil channel blocks forever (correct — it's a no-op case). But if the channel variable is not initialized at all, it could panic. Detection: code review. Mitigation: explicitly set `var reloadCh <-chan *config.Config` so nil is the zero value.
- **Reload during shutdown**: config change arrives while shutdown is in progress. Detection: bgCtx is cancelled, Watch exits, channel closes, select reads zero value. Mitigation: check for nil config from closed channel before calling Reload.

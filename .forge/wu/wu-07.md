# Parse llama-server events and collect metrics

## Outcome
Wire parses llama-server stderr into structured events and exposes a subscription channel. A monitor hub collects these events alongside polled llama-server HTTP metrics (/metrics, /slots, /health) and GPU hardware metrics from sysfs, then fans them out to subscribers. No user-visible UI yet — this WU builds the data layer that wu-08 consumes.

## Values
1. Correctness — parsed events faithfully represent llama-server output; unrecognized lines degrade to raw passthrough, never dropped or misattributed.
2. Zero disruption — existing slog debug logging continues to work. The event parser is additive, not a replacement of log output.
3. Minimal allocation — event parsing runs on every stderr line from every backend; avoid heap churn in the hot path.

## Context
- `internal/process/manager.go` — `lineLogger` (lines 379–401) buffers stderr and writes to slog. This is the tap point — replace with an `eventParser` that emits structured events *and* continues writing to slog. `procState` (lines 26–33) holds per-backend runtime state; add `startedAt` and `restarts` fields for uptime tracking. `Manager` (lines 37–46) needs a public method to return a read-only snapshot of all backend states and an events channel.
- `internal/config/config.go` — `Backend` struct defines model, port, pooling, etc. The snapshot should include relevant config fields so consumers don't need a config reference.
- llama-server stderr format (examples from real output):
  - Slot assignment: `slot 0 released` / `slot 0 is processing task`
  - Prompt eval: `prompt eval time =   142.50 ms /  1847 tokens (  0.08 ms per token, 12961.40 tokens/s)`
  - Generation eval: `eval time =  8234.12 ms /   412 tokens ( 19.99 ms per token,    50.04 tokens/s)`
  - Model loading: `llm_load_tensors: offloading 48 layers to GPU`
  - VRAM: `llm_load_tensors:        CUDA0 buffer size = 16588.80 MiB`
  - KV cache: `llm_load_print_meta: n_ctx_train = 131072` (and similar meta lines during load)
- llama-server HTTP endpoints (available on each backend's dynamic port):
  - `GET /metrics` — Prometheus text format. Key metrics: `llama_kv_cache_usage_ratio`, `llama_requests_processing`, `llama_requests_pending`, `llama_tokens_predicted_per_second`, `llama_prompt_tokens_per_second`, `llama_tokens_predicted_total`, `llama_prompt_tokens_total`.
  - `GET /slots` — JSON array of slot objects with fields: `id`, `state` (0=idle, 1=processing), `n_ctx`, `n_predict`, `prompt` (truncated), `next_token`, `tokens_predicted`, `tokens_evaluated`.
  - `GET /health` — JSON with `status` field: `"ok"`, `"loading model"`, `"no slot available"`.
- GPU metrics via sysfs (AMD/ROCm). These files are readable without root and provide real-time hardware telemetry:
  - `/sys/class/drm/card*/device/gpu_busy_percent` — GPU compute utilization (0–100).
  - `/sys/class/drm/card*/device/mem_info_vram_total` — total VRAM in bytes.
  - `/sys/class/drm/card*/device/mem_info_vram_used` — used VRAM in bytes.
  - `/sys/class/drm/card*/device/hwmon/hwmon*/temp1_input` — edge temperature in millidegrees C (divide by 1000).
  - `/sys/class/drm/card*/device/hwmon/hwmon*/power1_average` — power draw in microwatts (divide by 1000000).
  - GPU clock speed is available via `rocm-smi` but not reliably via sysfs across all cards. Omit for now — add later if a stable sysfs path is found.
  - Card identification: `/sys/class/drm/card*/device/vendor` (0x1002 = AMD), product name from `/sys/class/drm/card*/device/uevent` (PCI_SLOT_NAME) or via `rocm-smi --showproductname --json` at startup only.
  - Multiple GPUs: enumerate all `/sys/class/drm/card*/device/gpu_busy_percent` matches. Each match is a monitorable GPU. Single-GPU is the common case.
- This project uses Go 1.26 with `errors.AsType[T]` where applicable.

## Requirements

### 1. ServerEvent type
Define in `internal/monitor/event.go`:
```go
type EventKind int

const (
    EventSlotAssign EventKind = iota
    EventSlotRelease
    EventPromptEval
    EventGenEval
    EventModelLoad
    EventVRAMAlloc
    EventError
    EventRaw // unrecognized lines
)

type ServerEvent struct {
    Time       time.Time
    Backend    string
    Kind       EventKind
    Slot       int       // -1 for system-level events
    Tokens     int
    TokPerSec  float64
    DurationMs float64
    Message    string    // raw line for EventRaw, detail for others
}
```

### 2. Event parser
`eventParser` implements `io.Writer`. It buffers by newline (same as `lineLogger`), then for each complete line:
1. Attempts to match against known llama-server patterns using compiled regexes.
2. On match: constructs a `ServerEvent` with the appropriate `EventKind` and parsed fields.
3. On no match: constructs a `ServerEvent` with `EventRaw` and the line as `Message`.
4. Sends the event to a channel (non-blocking; drop if channel full — monitoring is best-effort).
5. Always writes the line to slog.Debug (preserving existing behavior).

The parser must handle these patterns at minimum:
- `prompt eval time = <ms> ms / <tokens> tokens (<per_tok> ms per token, <tok_s> tokens/s)`
- `eval time = <ms> ms / <tokens> tokens (<per_tok> ms per token, <tok_s> tokens/s)` (generation)
- `slot <N> released` / `slot <N> is processing`
- `llm_load_tensors: offloading <N> layers to GPU`
- `llm_load_tensors: <device> buffer size = <size> MiB`

Regex compilation must happen once at init, not per-line.

### 3. BackendStatus snapshot
Add to `Manager`:
```go
type BackendStatus struct {
    Name      string
    Model     string
    Port      int
    PID       int
    Healthy   bool
    StartedAt time.Time
    Restarts  int
}

func (m *Manager) Snapshot() []BackendStatus
func (m *Manager) Events() <-chan ServerEvent
```
`Snapshot()` acquires read locks and returns a copy. `Events()` returns a receive-only channel created at `Manager` construction time.

Add `startedAt time.Time` and `restarts int` fields to `procState`. Set `startedAt = time.Now()` in `launch()`. Increment `restarts` each time the supervise loop re-launches (not on first start).

### 4. Monitor hub
`Hub` in `internal/monitor/hub.go`:
- Created with the event channel from `Manager` and a list of backend addresses (from `Manager.Snapshot()`).
- On creation, calls `DiscoverGPUs()` to find available GPUs. Stores the `[]GPUInfo` for the poll loop.
- Runs a poll loop (1-second interval) that:
  1. Fetches `/metrics` and `/slots` from each backend's port.
  2. Calls `ReadGPUMetrics()` with the discovered GPUs.
  3. Fans out both backend metrics and GPU metrics to subscribers.
- Parses Prometheus text format to extract gauge values (simple line-by-line parser — no need for a full Prometheus client library).
- Parses `/slots` JSON response.
- Maintains current state: `BackendMetrics` per backend + `[]GPUMetrics`.
- Subscribers register via `Subscribe() (<-chan HubMessage, func())` where the returned func unsubscribes. Channel is buffered (64). Hub drops messages to slow consumers rather than blocking.
- `HubMessage` is a tagged union (type field) covering: snapshot, metrics tick, GPU metrics tick, server event, state change.
- `Hub.Snapshot()` returns the current full state synchronously for new subscriber bootstrapping (includes GPU metrics).

### 5. GPU metrics collector
Define in `internal/monitor/gpu.go`:
```go
type GPUInfo struct {
    Index    int    // card index from sysfs (e.g., 1 for card1)
    Name     string // product name if discoverable, otherwise "GPU <index>"
    SysPath  string // e.g., "/sys/class/drm/card1/device"
}

type GPUMetrics struct {
    Index       int
    Name        string
    BusyPct     int     // 0–100, from gpu_busy_percent
    VRAMTotal   uint64  // bytes, from mem_info_vram_total
    VRAMUsed    uint64  // bytes, from mem_info_vram_used
    TempC       float64 // degrees C, from temp1_input / 1000
    PowerW      float64 // watts, from power1_average / 1000000
}
```

**Discovery** (`DiscoverGPUs() []GPUInfo`):
1. Glob `/sys/class/drm/card*/device/gpu_busy_percent`.
2. For each match, extract the card index from the path.
3. Read product name from the `uevent` file in the device directory (parse `PCI_SLOT_NAME` or `DRIVER` line). If unavailable, fall back to `"GPU <index>"`.
4. Return the list. Empty list is valid — no GPU monitoring available.

**Polling** (`ReadGPUMetrics(gpus []GPUInfo) []GPUMetrics`):
1. For each `GPUInfo`, read the 5 sysfs files (busy, vram_total, vram_used, temp, power).
2. Parse each as integer, apply unit conversions.
3. If any file read fails, set that field to zero (partial data is fine — sysfs files can transiently fail).
4. The hwmon subdirectory name (`hwmon/hwmon*`) may vary. On init, resolve the glob once and cache the path. Re-resolve if the cached path fails (hwmon index can change across driver reloads).

Discovery runs once at hub startup. Polling runs on each hub tick (1s interval) — reading 5 small sysfs files takes <1ms.

**Tests**: Create a temp directory with the sysfs structure (`gpu_busy_percent`, `mem_info_vram_total`, etc.), write known values, pass the temp path to the collector, verify parsed output. Test partial failure (missing file) returns zero for that field.

### 6. Metrics parser
Parse the subset of Prometheus text format that llama-server emits. Only need to extract `float64` values from `# TYPE <name> gauge` / `<name> <value>` lines. No histogram, no summary, no labels parsing needed. Return `map[string]float64`.

### 7. Integration in Manager
In `Manager.launch()`, replace `lineLogger` with `eventParser`:
```go
parser := monitor.NewEventParser(m.log, name, m.eventCh)
cmd.Stdout = parser
cmd.Stderr = parser
```
The `m.eventCh` is created once in `New()` with buffer size 256.

- `go build ./...` must pass.
- `go test ./...` must pass.
- Do not modify files outside the Creates/Modifies list unless strictly required.
- The event channel must be non-blocking on send. If the channel is full, the event is dropped. Logging to slog must never be skipped regardless of channel state.

## Failure Modes
- **Regex mismatch on llama-server update**: llama-server changes its log format, regexes stop matching. All events become `EventRaw`. Detection: test with real log samples; monitor hub still functions (just no structured per-request data). Mitigation: `EventRaw` preserves the line for debugging.
- **Channel full drops events**: under high throughput, the 256-buffer event channel fills. Events are silently dropped. Detection: add a dropped-event counter to the parser, expose in snapshot. Mitigation: buffer size is configurable if needed; monitoring is best-effort by design.
- **Metrics endpoint unavailable during model load**: llama-server doesn't serve `/metrics` until healthy. Hub gets HTTP errors during startup. Detection: hub logs at debug level and returns zero metrics. No crash, no retry storm (1s poll interval is the backoff).
- **Stale port after swap**: during a model swap, the port changes. Hub continues polling the old port until it receives the next snapshot. Detection: HTTP errors on old port. Mitigation: hub re-reads ports from Manager.Snapshot() on each poll cycle.
- **No GPU sysfs files**: non-AMD system, container without device access, or no discrete GPU. `DiscoverGPUs()` returns empty list. Hub skips GPU polling entirely. Dashboard shows no GPU section. Detection: test with empty temp dir.
- **sysfs permission denied**: some systems restrict GPU sysfs to root or video group. Individual file reads return error, field set to zero. Detection: test with unreadable files. Mitigation: partial data is better than no data — show what's available.
- **hwmon index changes**: after GPU driver reload, `hwmon5` might become `hwmon6`. Detection: cached hwmon path returns ENOENT. Mitigation: re-glob on failure (at most once per poll cycle to avoid glob storm).
